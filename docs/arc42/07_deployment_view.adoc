== 7. Deployment View

=== 7.1 Deployment Context

The system is a local toolchain, not a distributed service deployment.
Execution topology is process- and filesystem-oriented.

Typical verified setup:

* Windows host with WSL2 Ubuntu distribution.
* Repository mounted under `/mnt/d/...`.
* Python virtual environment `.venv-wsl`.
* Local JDK and Byteman jar under `verification/tools/` (for proof scripts).

=== 7.2 Process and Thread Layout

Key runtime participants:

* Python CLI process.
* Optional watcher thread during stress iterations.
* Java process launched through generated shell script.
* Filesystem paths as integration channels.

=== 7.3 Filesystem Layout and Artifact Placement

[cols="2,3"]
|===
|Path pattern |Purpose

|`<scan-output>/Byteman.log`
|Static inventory report.

|`<scan-output>/generated-rules.btm`
|Generated Byteman rules.

|`<scan-output>/analysis-metadata.json`
|Optional generator metadata.

|`<run-dir>/run-with-byteman.sh`
|Generated launcher script.

|`<run-dir>/classes/`
|Compiled Java classes for stress execution.

|`<run-dir>/runs/iteration-*/runtime/byteman-runtime.log`
|Per-iteration runtime events emitted by helper.

|`<run-dir>/runs/iteration-*/watcher-report.jsonl`
|Per-iteration monitor report.

|`<run-dir>/stress-summary.json`
|Aggregate stress summary.

|`<run-dir>/stress-results.json`
|Full config + summary + iteration payload.
|===

=== 7.4 Operational Modes

* Development mode: run CLI directly per command.
* Verification mode: run scripted flows under `verification/scripts`.
* No long-lived daemon/service mode exists in current implementation.
