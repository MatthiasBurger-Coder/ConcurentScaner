== 9. Architecture Decisions

NOTE: No formal ADR directory is present in the repository. The following decisions are inferred from code and tests.

=== AD-01: Use Python as orchestration language

*Context:* toolchain needs file processing, process orchestration, and testing-friendly modularity.

*Decision:* implement orchestration in Python modules under `byteman_static`.

*Consequences:*

* fast iteration and straightforward testability,
* direct subprocess and filesystem integration,
* no compiled orchestrator artifact.

=== AD-02: Prefer AST parsing, keep regex fallback

*Context:* parser dependency availability may vary by environment.

*Decision:* `select_parser_backend()` attempts tree-sitter backend first, then fallback parser.

*Consequences:*

* broader environment operability,
* reduced fidelity in fallback mode,
* explicit limitations carried in analysis output metadata.

=== AD-03: Use generated Byteman rules + helper class contract

*Context:* runtime observability requires instrumentation with minimal manual rule authoring.

*Decision:* generate rules and call helper methods (`onMethodEnter`, `beforeFieldAccess`, ...).

*Consequences:*

* reproducible instrumentation artifacts,
* helper class API becomes integration contract,
* runtime evidence quality depends on helper implementation and emitted fields.

=== AD-04: File-based runtime/event/report integration

*Context:* system should run locally and be script-friendly.

*Decision:* use files for runtime log ingestion and JSONL/JSON output.

*Consequences:*

* simple and auditable integration,
* easy post-mortem analysis,
* potential filesystem I/O bottlenecks at large scales.

=== AD-05: Heuristic overlap detection with threshold escalation

*Context:* exact race proof is out of scope.

*Decision:* classify overlaps into suspect levels based on counters and thresholds.

*Consequences:*

* practical signal for suspicious concurrency behavior,
* false positive/negative risk remains,
* thresholds must be interpreted as heuristic confidence, not proof.

=== AD-06: Scenario-driven stress orchestration

*Context:* need repeatable and configurable stress workflow.

*Decision:* define scenario JSON with defaults + CLI overrides.

*Consequences:*

* reproducible stress runs,
* explicit run configuration in output payload,
* correctness depends on scenario quality and environment setup.

=== AD-07: Linux launcher generation instead of direct JVM invocation in Python

*Context:* Byteman Java agent setup requires repeatable JVM options and env handling.

*Decision:* generate shell wrapper and execute it.

*Consequences:*

* clear launch contract and inspectable script artifact,
* Linux/Bash dependency for execution path.
